# 赛题 4：模型无关的检索、推理与核验研究（2026-10-04）

## 研究边界

目标是让同一套资料处理流程可以接任意合规的离线开源生成模型。此次以既有 DeepSeek API 结果作**研究对照**；它不进入训练、伪标签、最终参赛系统或正式提交。当前接口别名 `deepseek-flash` 已指向 V4.1 Flash，也不等同于赛题表中标注的 V4 Flash。所有离线开发评测只读取训练集金标；760 题测试集没有金标，不用于调参。方案必须能迁移到相同文件协议、相近任务的其他数据集，不能根据题号、领域名称或已知答案写死规则。

平台公开权重是 A/B/C = 60/30/10，每档答案/证据链/置信度与拒答 = 40/40/20。答案内含关键事实 25、字符 F1 10、语义 5；证据内含节点 25、结构与顺序 15。细项自动评分公式尚未公开；本地指标是可重复的代理指标，不冒充官方分数。

### 2026-10-04 首次线上得分与本地估分边界

用户提交的 `deepseek_flash_full_760.json` 平台反馈为 A **64.96**、B **51.35**、C **51.67**、总分 **59.55**。按公开公式计算，`0.6×64.96+0.3×51.35+0.1×51.67=59.548`，与总分四舍五入一致。A、B、C 各自贡献约 38.976、15.405、5.167 分；按测试题量 210/350/200 换算，在档内等权的前提下，每道 A/B/C 题对总分的理论满分贡献分别约 0.2857/0.0857/0.0500 分。**“档内等权”尚待官方确认，不能当作已公开单题公式。**

赛事截图中的 DeepSeek-V4-Flash 基线列出 A/B/C 为 67.94/52.13/52.75，另列综合 57.61。三档按同一公开公式加权却得到 **61.678**，与表列综合分相差 **4.068**。因此，对照各档，本次提交低于该基线 2.98/0.78/1.08 分；但不能同时据这三档分数和表列的 57.61 得出可靠的总分排名结论。需要向主办方核实该表是否混用了不同数据版本、权重、四舍五入前分数或其他口径；单靠常规四舍五入无法解释 4.068 分。

这不是 DeepSeek 一列的孤例：基线表中图方法、BM25+BERT、普通 RAG、Llama3-8B 的 A/B/C 按 60/30/10 加权分别是 **22.012/43.688/40.749/50.206**，但表列综合分分别是 **25.52/40.20/40.48/50.85**。至少存在表格或评测口径不一致；目前不能判定具体原因。相比之下，我们自己的线上提交四个数字彼此吻合。

**之前“无法自己打分”的表述不准确。** `evaluate_baselines.py` 已能用训练集金标按题计算答案字符 F1、证据节点和有向边 F1、完整链匹配、拒答正确率，并可用本地 BGE 得到答案语义余弦；`experiments/check_published_scores.py` 可核对任何官方 A/B/C 分数的总分。我们可以用公开的 25/10/5、25/15、20 权重组装一个**明确注明自选细则的本地代理评分器**，在材料包留出验证集上比较方案变化。它不能精确重算这 760 题的 59.55，原因是测试金标不公开，而且 `required_facts` 的语义命中、字符切分、语义模型和归一化、证据结构 15 分、confidence 标定的具体算法未公开。当前 `required_fact_coverage` 是字面/字符启发式，100 道训练题仅得 0.0623，明显不能当作官方关键事实得分。后续应把它作为一个独立的估分误差源，使用人工审查的训练集小样本与语义匹配器做敏感性分析，不能拿它直接换算官方百分制。

为使差异可复查，`experiments/score_proxy_from_diagnostics.py` 把现有训练集指标代入公开分项权重：100 道旧 DeepSeek 训练题的五项代理合计 **40.513/80**，其中“关键事实 25 分”仅得 **1.558**，结构 15 分采用人为设定的“边 F1 与完全匹配各半”，置信度 20 分尚未估算。这是**代理评分方法的诊断**，不是模型真实总分；它暴露出当前事实匹配器过严，且训练题与平台盲测题不同，不能据此宣称与 59.55 相差约 19 分。

同一批 100 道训练题、同一代理口径下，图方法 **34.842/80**、BM25+BERT **34.498/80**、DeepSeek **40.513/80**。它能识别本地 DeepSeek 相对两个规则基线较强，但图方法与 BM25+BERT 的次序与赛事基线表不同，说明当前复现与估分均尚不足以预测各方法的线上名次。

## 当前代码与数据发现

仓库已具备原文读取、事件与边读取、BM25+BGE 排序、图路径、生成接口、格式校验。旧 RAG 输入在取前 k 篇文档时，B/C 没有因果边，候选链常退化为一个事件；旧模板基线还会按 `question_type=unanswerable` 直接拒答。这两个行为不能作为高质量、可泛化的答案策略。

`experiments/audit_retrieval.py` 对训练集 1000 个材料包、7196 题执行了**不调用模型、不读取测试集**的审计。6339 道题至少有一条非空金标证据链。下面的“完整链覆盖”是：检索结果包含任意一条金标链的全部事件 ID；有多条金标链时取最好的一条。它是乐观的检索上限，不等于证据链预测正确率。

| 检索候选 | 平均候选事件数 | 完整金标链覆盖率 | 平均最优金标链节点召回 |
| --- | ---: | ---: | ---: |
| BM25 前 3 | 3.00 | 42.37% | 68.38% |
| BM25 前 3 + 题目明确点名的合法事件 ID | 3.42 | 56.51% | 78.10% |
| BM25 前 5 | 5.00 | 61.38% | 82.88% |

题目中 83.8% 明确出现了事件 ID。`prospective` 的最短金标链平均 3.65 节点，BM25 前 3 的完整链覆盖只有 18.03%；`multi_hop_reasoning` 平均 4.84 节点，前 3 覆盖只有 6.45%。因此固定 `top_k=3` 并压缩掉其他材料不适合这些题。按问题显式锚点补齐候选只需解析输入协议，不涉及偷看答案；后续必须用独立验证集确认它是否提高最终答案与链质量。

在种子为 `20261004` 的固定随机 40 个训练材料包（288 题、其中 254 题有非空金标链）上，BM25 与仓库现有 BM25+BGE 的对照如下。二者是同一批问题、同样的三候选预算；结果显示现有 BGE 混排增益很小，不能将“加入向量检索”本身视为主要突破。

| 检索方法 | 前 3 完整链覆盖 | 前 3 + 锚点完整链覆盖 | 后者平均候选数 |
| --- | ---: | ---: | ---: |
| BM25 | 44.49% | 58.66% | 3.44 |
| BM25+BGE | 44.88% | 59.84% | 3.45 |

以上 40 包用于方法探索，不是冻结保留验证集；如果按它们调权重，必须另选材料包复核。

**锚点不能升级为答案硬约束。** 有明确合法事件 ID 且有非空金标链的题中，追溯题 98.63%、反事实题 98.64% 可找到一条包含全部题目点名 ID 的标准链；预测题仅 25.99%，其显式 ID 在最佳金标链中的平均覆盖也只有 57.85%。预测题常罗列截至某时点已知的多个事件，金标只选择其中一条解释路径。因此保留锚点能防止检索遗漏，但“把题目所有 ID 都塞进最终链”的规则是错误的。最终链必须由问题目标与因果证据选择，不能直接复制问题中的事件列表。

训练集的多条标准链不能强制合并为一条；已有训练金标还出现相邻证据节点未在给定边表中直接出现的情形。因此给定边是高价值线索，不能成为否定一切其他有原文支持的关系的硬门槛。答案仍应回到原文段落核实。

## 学习式事件检索的初步结果

`experiments/train_event_retriever.py` 用训练金标把“事件是否出现在任一可接受证据链”作为弱监督目标，训练一个轻量梯度提升排序器。特征来自 BM25 排名、问题与事件文字重合、题目点名的合法 ID、候选位置、题型和可选图节点度数；不使用答案文本、测试金标或 DeepSeek 输出。按材料包随机划分 800 包训练、200 包验证，分别模拟“提供因果图”和“隐藏因果图”。

| 未见材料包上的检索 | BM25 前 3 完整链覆盖 | 学习排序前 3 完整链覆盖 | 样本 |
| --- | ---: | ---: | ---: |
| 有给定边视图 | 41.42% | 74.41% | 1270 道有非空金标链的题 |
| 隐藏边视图 | 41.42% | 74.02% | 同一批 1270 题 |

这是**候选召回指标**，不能当作答案或线上分数。该训练集中的模板、事件编号和材料结构高度相似，随机整包留出仍可能高估跨数据集泛化。下一步必须去掉 ID/位置/题型特征，并整领域留出；只有仍能改善时，才考虑把模型接入生成流程。

第一轮去捷径消融（将“题目是否点名此 ID”、候选编号位置、题型独热特征全部置零）后，同一 200 包验证集前 3 完整链覆盖仍为：有给定边 **70.08%**、隐藏边 **58.03%**，对照 BM25 的 41.42%。提升没有完全来自题号和题型模板，但隐藏边时损失明显；必须继续做整领域留出和错误样本分析。

进一步整领域留出：完全排除“自然灾害”228 包，仅用其余 772 包训练，同样去掉显式 ID、编号位置与题型特征。在自然灾害领域 1450 道有非空金标链的题上，BM25 前 3 完整链覆盖 **34.41%**；学习排序在有图时 **71.86%**，隐藏图时 **52.34%**。这比随机整包切分更支持跨领域迁移，但仍是同一赛事文件协议与题目生成分布，不能证明跨数据集泛化；还需第二领域复核和外部数据集验证。

第二个整领域留出为“政治外交”232 包，其余 768 包训练，同样去捷径：BM25 前 3 完整链覆盖 **46.83%**；学习排序有图 **68.41%**、隐藏图 **55.21%**。两个领域都出现正向收益，但隐藏图条件下增益较不稳定，需要把 B/C 的文档语义与关系推断另作重点。

进一步把验证包模拟为 C 档“只给文档与问题”，相同去捷径模型的前 3 完整链覆盖由 BM25 的 **25.35%** 提高到 **29.53%**，提升远小于 A/B 模拟。C 档更需要可靠的事件抽取和跨文档关系识别；该数字仍只是候选召回，不能换算线上 C 分数。

## 拟实验的通用流程

1. **资料标准化**：文档、事件、边转为统一 `EvidenceRecord`（ID、原文句子、来源文档、事件字段、可选边）。不推断字段缺失就意味着关系不存在。
2. **问题锚点与双层检索**：解析题目明示的合法 ID；BM25+BGE 排序事件/句子，保留锚点，再按给定边或句子关联做有限扩展。输出候选集、分数和来源，保留多个可能路径。候选预算按检索充分性决定，不能固定为三篇。
3. **证据充分性检查**：检查问题的主要实体、原因与结果是否在候选中都有来源句，是否有冲突、缺环；不足时扩大检索或要求生成模型明确保留不确定性。
4. **生成与核验分离**：生成模型只读所给材料与候选提示；其证据链、答案事实、拒答分别校验。候选是提示，不是硬约束；不能因为检索器漏掉内容就禁止模型使用原文中真实存在的 ID。
5. **统一输出**：沿用现有五字段解析与校验，保留最终结果与不含密钥的中间日志。正式系统用离线开源权重替换研究 API。

## 实验设计与通过门槛

先用训练集按材料包划分开发/保留验证集，冻结划分，禁止同一材料包问题跨集。既有 DeepSeek 100 题结果只作探索；新的对照需要在同一批保留验证题上重新运行原始全量提示与改进流程。每条路线至少报告：金标链节点/有向边 F1、对多条金标的 exact match、答案字符 F1、关键事实覆盖的人工核对样本、正确拒答率、模型请求数、输入 token/字符数、延迟。未知官方公式部分只报告代理指标和原始样例，不编造精确官方分数。所有中间提示与预测不得包含训练金标。

候选消融顺序：① BM25 前 k；② 加题目锚点；③ 加句级 BGE 与邻域扩展；④ 证据充分性与缺口检索；⑤ 生成后核验。若模块只提高检索覆盖而降低答案/链指标，应撤回或限定适用场景。最终至少在另一组未参与调参的材料包与 A/B/C 三种输入视图上验证，确认不是题号模板或单一领域特化。

## 当前已验证与未验证

- 已验证：训练集的 BM25 全量审计、40 包 BM25/BGE 配对检索审计、数据路径与现有接口结构。
- 已验证的**负结果**：以既有 DeepSeek 训练集前 100 题中的 12 题为探索切片，配对比较原始全量提示与“BM25 前 3 + 问题锚点的证据提示 + 原文全量”后，答案字符 F1 为 0.4273→0.4306，但链 exact 为 0.5000→0.4167、节点 F1 为 0.8551→0.7903、边 F1 为 0.6630→0.6199。该切片是探索样本，不能外推总体；特别是长链预测题被短候选提示误导。后续应验证候选预算和路径级提示，不能直接沿用这一版。
- 进一步针对同一批中的 3 道 `prospective` 题做消融：把候选扩大到前 8，链节点 F1 仍由原始全量提示的 0.7291 降为 0.5427；将给定边的完整路径作为提示后，节点 F1 回到 0.7291，但没有超过原始输入，答案字符 F1 由 0.2396 降到 0.2177。三题只用于定位失败机制，不能作总体效果结论。这说明仅靠增加候选数量也未解决“生成时只保留预测后缀、漏掉上游链”的问题。
- 对 6 道探索题用同一次运行的初稿与“原文事实/证据链复核”终稿配对，模型修改了 5 道；答案字符 F1 从 0.2580→0.2656，但证据节点 F1 从 0.5690→0.5500、边 F1 从 0.5750→0.5333。另有一道因模型两次引用材料外 ID 而保守拒答。通用的“让同一模型再检查一遍”也尚未显示净收益；后续若做核验，应有明确的触发条件和独立证据核对，而不是无差别二次生成。
- 学习排序器从其**未见过的 200 个训练材料包**中另选 16 题，每个题型 4 题、题包互异，并避开上述探索题。前 8 题作为开发观察：原始全量输入 vs 学习排序前 3 候选提示加全量原文，答案字符 F1 **0.4803→0.4582**，证据链 exact **3/8→5/8**，节点 F1 **0.8257→0.8355**，边 F1 **0.7019→0.7192**。其中两道反事实题改善，两道前瞻题有截断上游路径问题；样本太小且指标方向冲突，不能宣布提分。
- 根据前 8 题的错误，提示中增加通用的“按题意保留从起点到目标的必要上游/中间环节；直接关系勿添无关下游”，然后只在**另 8 道未测试题**上做同模型配对。答案字符 F1 **0.5211→0.5105**，链 exact **3/8→3/8**，节点 F1 **0.7528→0.7884**，边 F1 **0.5714→0.5619**。这组留出题没有证实最终答案和完整链的净改善。因此学习排序虽能提高候选召回，目前的“多给候选提示”仍不能取代更好的事实生成与路径选择；不能把它提交为已验证的优化成果。
- 未验证：改良流程相对原始 DeepSeek 提示的答案与证据链净提升；离线开源模型的最终效果；线上隐藏集分数。
- 实验记录位于忽略的 `outputs/`，研究文件与审计脚本可复现。任何模型权重/API 来源、版本与成本都应记录在实验日志中。
