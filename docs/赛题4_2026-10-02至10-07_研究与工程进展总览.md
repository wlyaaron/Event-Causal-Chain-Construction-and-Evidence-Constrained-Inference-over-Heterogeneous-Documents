# 赛题 4：从 DeepSeek 研究基线到 Qwen3.5-9B 离线推理的进展总览

> 整理日期：2026-10-07。本文依据当日 GitHub 提交、仓库内实验记录与已归档的运行结果，记录 2026-10-02 至 10-07 的工作。它是阶段总结，不是新的赛事成绩报告。文中“平台分数”“训练集本地代理”“无 gold 盲测诊断”口径不同，不互相换算。

## 1. 起因、任务与证据边界

赛题要求从异构文档回答因果问题，输出答案、按因果方向排列的证据 ID 链和置信度。A 档提供事件与因果边，B 档提供候选事件但须判断关系，C 档涉及事件抽取、冲突与无答案情形；公开权重分别为 60%／30%／10%，答案、证据链、置信度与拒答分别占 40%／40%／20%。训练集有 **1000 个材料包、7196 题**；抽样测试集有 **760 题**（A 210、B 350、C 200），**没有公开 gold**。最初的问题是：直接把完整材料交给生成模型，能否形成有效基线；在保持合规的前提下，检索、路径提示和离线微调又分别能改善什么。

赛事要求正式预测由符合条件的离线开源模型生成，不允许直接使用闭源托管 API，也不允许人工标注测试答案。因此 DeepSeek API 仅作研究诊断；其逐题输出不能进入 Qwen 的训练、蒸馏、伪标签或正式提交。测试集只用于输入完整性和输出结构核查，不用于调参。平台评分细则没有全部公开，仓库的字符 F1、语义、关键事实、节点／边及链完全匹配均是**本地代理**。

仓库目前有两条提交线：GitHub `main` 停在交接提交 [`50e81d88`](https://github.com/wlyaaron/Event-Causal-Chain-Construction-and-Evidence-Constrained-Inference-over-Heterogeneous-Documents/commit/50e81d88)，包含模型外流程与数据研究；后续离线 Qwen 准备、盲测运行器和守护代码在 `task4-server-sft-20261006` 分支，整理前的远端 HEAD 为 [`48eb1cb9`](https://github.com/wlyaaron/Event-Causal-Chain-Construction-and-Evidence-Constrained-Inference-over-Heterogeneous-Documents/commit/48eb1cb9)。两分支不能混称为已经合并。训练 JSONL、模型权重、研究 API 输出和预测文件都位于 Git 忽略的 `outputs/` 或另行归档处，GitHub 只保存可复现代码、配置及汇总记录。

### 2.1 直接 DeepSeek：先建立可运行基线

最初实现将多文档材料及题目直接送入 `deepseek-flash` 兼容接口，以统一解析和校验程序收集答案及证据链。10 月 4 日用户提交研究输出，平台反馈 **59.55**，分档 **64.96／51.35／51.67**；按公开 60／30／10 权重加权为 59.548，与总分一致。这是目前**唯一有平台反馈的本项目分数**。文件名沿用了 V4 Flash 叫法，但当时 `deepseek-flash` 服务别名已指向 **V4.1 Flash**，不能与赛事截图中“DeepSeek-V4-Flash”视作同一模型。该次运行还跨过格式和拒答修复提交 `949e5e52`，已保存原始输出与阶段源码快照，不能用单个 Git 提交充当全程版本。

基线暴露了需要解决的问题：证据可能在多篇文档中且链较长；格式失败需可追踪地修复；`unanswerable` 题有的 gold 包含解释与证据，不能按题型一律拒答。赛事截图中的 DeepSeek 基线 A/B/C 67.94／52.13／52.75 按公开权重应为 61.678，却另列综合 57.61，表内口径尚未澄清；不能据此声称超过或低于其综合基线。

### 2.2 设计流程并继续调用 DeepSeek：检索进步与生成进步分开看

团队先独立实现 graph、BM25+BERT 和 RAG 对照，检查“证据是否进入候选集”。在 6339 道有非空金标链的训练题中，BM25 前 3 的完整链候选覆盖为 **42.37%**；加入题目明示的合法事件 ID 后为 **56.51%**，前 5 为 **61.38%**。学习式事件排序也提高过候选覆盖，但同模型生成实验没有稳定改善最终答案或完整链。这说明检索上限是瓶颈之一，也说明“检索命中”不可直接写成“模型答对”。

随后提出 A 档**问题条件化局部因果路径**：在给定图中围绕题目锚点搜索有向路径，同时保留边类型、等级及原文片段，交给同一 DeepSeek 别名判断。文献中的 RoG、Beam Retrieval 启发路径候选保留；关于图文联合与长证据使用的论文支持提出假设，但并未证明本赛题必然提分。工程上用不同材料包的冻结题目清单做配对比较，并把候选覆盖、答案、节点／边、链 exact 分开计量。

两组共 23 道有 gold 的 A 题，原提示→新路径提示的本地代理：答案字符 F1 **.4692→.4880**，节点 F1 **.7481→.8302**，边 F1 **.5917→.7217**，链完全匹配 **10/23→13/23**。但独立第二组 11 题的答案字符 F1 **.4678→.4566**、语义 **.8064→.7919**，链 exact 仍为 **5/11**；有题因路径过短而丢失必要上游。更早的关系说明、锁链再改答案试验也出现边 F1 或答案下降的负结果。因此只能说新提示有证据指标信号，**答案和完整链收益尚不稳定**。

10 月 6 日用新 A 路径、原 B/C 输入对 760 道无 gold 题作完整 DeepSeek 研究复跑。同期 A 原提示→新提示的相邻节点“可在给定边表直接找到”的比例 **84.0%→97.9%**，平均链长 **4.14→3.60**；这证明提示改变了链选择，也提示长链被截短的风险。B/C 未更换输入，B 档跨次调用拒答 **66→79**，可见模型调用波动。新复跑**没有新的平台分数**，更不能以边表一致性代替 gold 正确性。

### 2.3 数据准备：让监督标签可追溯、让评估真正隔包

数据脚本从赛事训练原始文件重建视图，不读取 DeepSeek 输出。固定清单 `experiments/finetune_split_20261005.json` 按材料包及完全相同文档分组，fit／validation／holdout 为 **801／101／98 包**。当前 v3 A、B 视图各 **5767／709／702** 行，C 视图 **5672／706／685** 行（顺序均为 fit／validation／holdout）。每题完整原始 gold 保留在独立 sidecar；有多条可用链时，每次监督只选**其中一条完整原链**，不拼接不同路径。训练目标不凭题型强制拒答，也不伪造数值 confidence。

审计标出 **18** 题金标链引用缺失事件、**789** 题存在给定边表未列出的链步骤、**93** 道 `unanswerable` 有解释性答案或证据、**703** 题缺 `required_facts`、**2722** 题有多条 gold 路径。缺边不自动等于错标；跨划分同文问题加答案的 **498** 题保留标记用于分层报告，而非直接删除。训练集外部增强暂未加入，因为许可、任务适配、重复及赛事披露要求尚未核实。

用实际 Qwen tokenizer 和 LLaMA-Factory `qwen3_5_nothink` 模板审计完整消息长度与 gold 证据位置。九个 split/view 的 gold 证据 ID 最终均能在可见文档或事件记录中定位。两轮混合源数据 **11562** 行；16K 配置筛到 **11538** 行，**24** 条超长行显式列入 manifest，未静默尾截断。8K 会让大量训练样本超长且部分 gold 证据落在窗口外。A/B/C 混合、逐轮多参考、图缺步、解释性无答案和长上下文均是后续消融设计，**不是已经取得的模型收益**。

### 2.4 模型选型与微调链路：理论、实现、实测三层

因正式方案须使用离线开源权重，且材料较长、需要结构化答案，团队在模型选型讨论后先选 **Qwen3.5-9B** 做小参数主线，保留较大模型作为以后预算允许时的比较对象。其官方模型卡给出 Apache-2.0 许可、9B 规模和长上下文能力；模型宣称的上下文上限并不等于单张 GPU 能以该长度训练。固定官方权重修订和文件哈希，便于复现。

**文献依据**：LoRA 用低秩矩阵更新，QLoRA 用 4-bit 冻结底座加 LoRA 降低权重显存；长上下文证据位置和证据歧义研究提示要审计截断与多参考标注。**开源实现来源**：采用上游未修改的 [LLaMA-Factory v0.9.5](https://github.com/hiyouga/LlamaFactory/releases/tag/v0.9.5)，固定提交 `7af909522a951e3ad9f022ea6f88b6755257eaa5`，该版明确支持 Qwen3.5；Liger Kernel 用于降低长序列全词表损失的显存。Qwen3 官方列出多种可用微调框架，Qwen3.5 模型卡没有要求“必须用 LLaMA-Factory”。**本题工程假设**：4-bit NF4、double quant、BF16、LoRA rank 16、学习率 `1e-4`、有效 batch 8、A/B/C 混合与一轮基线均需验证集比较，不是论文给出的最优参数。

新服务器实测单卡 RTX 4090（49140 MiB），建立独立环境，保留系统盘原有 LLaMA-Factory 与已有工作。短样本 4K／两步 QLoRA 冒烟成功；首次 16356 token 一步训练在全词表交叉熵处 OOM，启用 Liger 后**同一长度一步成功**，训练段 **82.92 秒**。这解决了该压力样本的一步显存问题，却不能保证全轮稳定。按 11538 行、约 8282 万 token 与各长度单步时间估算，完整一轮约 **70–100 小时**，仅是预算预测。正式一轮 SFT、validation/holdout 评估、置信度校准均**尚未完成**；守护脚本只通过不关机演练。

### 2.5 用基础 9B 非思考模式替换生成器：完成全量离线运行

在与最新主线相同的 A 新路径、B/C 原输入下，加载官方 **Qwen3.5-9B 基础权重**，不加载 LoRA。非思考模式 `enable_thinking=False`、BF16、Transformers、单题串行、确定性生成，先用 tokenizer 审计 760 题：平均提示 **5048.7 token**，最长 **7343**；加 1536 输出预算仍小于 16K，未截断材料。全量 JSON 通过覆盖、字段、证据 ID 等校验，总模型计算时间 **4191.15 秒，约 70 分钟**。

| 无 gold 输出行为 | A（210） | B（350） | C（200） | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 精确输出“无法确定” | 70 | 196 | 126 | **392** |
| 平均证据链节点 | 2.452 | 1.966 | 1.620 | **2.009** |
| 首轮格式重试 | 18 | 47 | 18 | **83** |
| 两轮失败后的格式回退 | 0 | 6 | 3 | **9** |

同流程 DeepSeek 研究复跑的拒答数为 A/B/C **17／79／56**。本地 9B 基础模型表现得更保守，链也更短；九道格式回退被强制拒答是明确负结果。但两者模型、解码和服务不同，760 题又无 gold，**不能把拒答更多直接判为能力更弱、正确率更低或平台分数下降**。该输出没有提交赛事平台，也没有进入训练集。

### 2.6 思考模式：先限制预算，再启动全量任务

官方 Qwen3.5 模型卡说明默认思考并给出采样参数。本项目参考 **Qwen3 教程**的两段思考预算做工程适配：先允许最多 1024 个思考 token，未自然结束则插入结束提示与 `</think>`，再生成最终 JSON。该教程并非 Qwen3.5-9B 效果保证。早期自然思考样例曾连续碰到 2048／3072 token 上限而没有结束标记，故保留为负结果；随后使用训练集固定验证包中的 12 题检查格式和小样本代理。12 题均得到有效最终 JSON，其中 **11** 题需强制结束思考、**1** 题需格式修复；答案字符 F1 **.2904**、节点 F1 **.6625**、链 exact **.4167**。样本极小，不能与完整验证或平台分数等同。

batch 2 的三题试跑没有显示可信的每 token 吞吐改进，正式运行仍选 batch 1。760 题最大输入 **7341 token**，预留 3072 输出仍低于 16K；全量思考模式作业于 10 月 7 日启动，附带推理完成后检查 JSON 和 GPU 空闲的关机守护。**截至本文整理，没有经核实的 760 题最终文件、完整耗时、准确率或平台反馈**。若任务结束，须先依据守护状态、进度和 `task4_core.validate_file()` 核实，再单独续写结果；不从启动日志推断完成。

## 3. 阶段结果、失败与下一道验证门槛

目前可以确定三点。第一，直接 DeepSeek 研究基线得到一次平台反馈 **59.55**，但托管 API 不构成正式离线方案。第二，问题条件化路径提高了若干训练题的证据节点／边代理和盲测输出与给定边表的一致性，却也缩短长链，独立配对组未稳定改善答案或完整链。第三，Qwen3.5-9B 基础模型已完成**非思考模式**全量离线流程核查；其高拒答、短链和格式回退需要用有 gold 的包隔离验证集定位原因，而不能通过 760 道无 gold 题判分。

下一道实证门槛是按固定 fit／validation／holdout 划分完成**正式 QLoRA SFT 与消融**，在同一模型和推理入口下报告 A/B/C 分档的答案字符 F1、语义、关键事实覆盖代理、节点／边 F1、链 exact、拒答及训练／推理成本，并对多参考、图缺步、模板同文问答、解释性无答案和长材料分层。公开权重最多能支持明示假设的 80 分代理汇总；confidence 的数值只能从 validation 预测校准。思考模式全量输出即使完成，也仍需上述有 gold 评估才能判断其是否有益。未经用户授权，不向赛事平台提交新的预测。
