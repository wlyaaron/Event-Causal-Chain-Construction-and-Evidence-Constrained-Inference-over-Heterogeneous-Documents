## 二、任务为什么要求同时研究流程和模型

题目要读取异构文档，输出答案、因果顺序的证据 ID 链与置信度。A 档给文档、事件和因果边；B 档给候选事件但要自行判断因果；C 档还涉及事件抽取、冲突与无法确定。公开权重如下；公开的是分项权重，细项自动评分算法并未全部给出。

| 档位 | 测试题数 | 公开总分权重 | 输入差异与主要困难 |
| --- | ---: | ---: | --- |
| A | 210 | 60% | 有给定因果图，但题目所需局部路径、长链范围及图缺步仍需判断 |
| B | 350 | 30% | 有事件列表，没有现成因果边，不能把相关性直接当因果 |
| C | 200 | 10% | 材料和问题更开放，存在冲突、反事实及证据不足 |

答案占 40%（关键事实 F1 25、字符 F1 10、语义相似度 5），证据链占 40%（证据节点 Precision／Recall／F1 共 25、因果链结构与顺序 15），置信度与拒答占 20%。这些是[赛事评测页截图](赛事网页内容/05_评测.png)公开的**评价项目和权重**；截图还举例说明多参考链比较、遗漏关键事实和额外错误事实的扣分，但未公开完整逐题计算程序。仓库训练集为 **1000 个材料包、7196 题**，测试集 **760 题无 gold**。赛题要求正式预测使用合规的离线开源模型，不能直接以闭源托管 API 产生正式参赛预测，也不能人工标注测试答案。因此早期 DeepSeek API 是研究对照；其输出从未用作 Qwen 微调、蒸馏或伪标签。模型外流程和离线模型必须分别评估。

### 2.1 哪些由赛事给定，哪些是我们的可复算指标

这里必须区分**评价目标／权重**与**评分算法**：主办方给出要评什么、每项占多少，也给出部分示例；我们的脚本在有 gold 的赛事训练集上实现了可复算的近似算法。即使名称相近，本地分项的具体数值也不等于隐藏评测脚本分数。下表把来源、用途和可解释范围对应起来。

| 评价方向 | 赛事公开的项目与权重 | 我们实现的量及用途 | 主要差别／边界 |
| --- | --- | --- | --- |
| 档位汇总 | A／B／C 占总分 60%／30%／10% | 本地分档报告并按 0.6／0.3／0.1 汇总，避免题数最多的 B 档自然主导 | **权重来自赛事**，各档内部本地分数仍是代理 |
| 关键事实 | 答案项 25 分：`required_facts` 覆盖 F1，并考虑遗漏及额外错误事实 | 字面／字符覆盖 $K^{\rm lit}$ 追踪明确写出的事实；早期语义阈值覆盖 $K^{\rm sem}$ 检查同义表达 | 两者主要测**召回**，未可靠识别额外错误事实，不能称为官方关键事实 F1 |
| 答案字符 | 答案项 10 分：字符 F1 | 归一化后的字符多重集 F1 $C$，检查具体答案文本的重合与遗漏 | “字符 F1”方向官方给定；归一化、多参考取最大等**计算细节由我们定义** |
| 答案语义 | 答案项 5 分：语义相似度 | 本地 BGE 余弦 $S$，检查改写后是否仍接近 gold | 编码器、截断长度和余弦到分数的映射由我们选定 |
| 证据节点 | 证据链项 25 分：节点 Precision、Recall、F1；多参考题与得分最高的标准链比较 | 事件 ID 集合 F1 $N$，检查是否引用到 gold 节点 | 本地逐分项取最佳完整备选链，节点与边可能对应不同金标；官方完整比较公式未知 |
| 链结构／顺序 | 证据链项 15 分：赛事提到因果边 F1、方向准确率、链路匹配 | 有向相邻边 F1 $D$ 与完整链相等 $X$，各占本地 7.5 分；分别看局部连接与整条路径 | **各半是我们的设计**；未单独实现官方所述方向准确率分项 |
| 置信度／拒答 | 20 分：confidence 与答案正确性匹配；无答案时看是否正确输出“无法确定”，confidence 为 `null` | 先分开报拒答次数和有 gold 时的拒答正确性；未来只用 validation 做局部成功概率校准与 Brier 诊断 | 没有把此项硬算成 20 分；拒答次数不是拒答正确率，Brier 不是官方得分 |
| 流程与资源诊断 | 赛事允许报告推理时间、资源消耗，但未给它们上述分项权重 | 候选完整链覆盖、给定边支持率、链长、格式修复率、生成 token／时间／显存，用于定位检索、约束与成本问题 | **均为自设工程诊断**；尤其无 gold 的 760 题不能由这些量推导正确率 |

因而 59.55／58.56／41.71／54.67 是四次提交获得的**平台评测结果**；下面的 $P_{ABC}$ 是我们利用公开权重整理的**训练集本地代理**；760 题的拒答数、链长和耗时是**无 gold 行为统计**。只有同一层级的数字才能直接比较，不能拿本地 80 分代理减线上百分制分数。

官方明确了答案、证据和置信度／拒答的评价方向及权重，但没有公开完整逐题计算函数。因此我们选择**逐项可复算的代理**：答案一侧同时看文字重合、语义和事实；证据一侧同时看节点集合、相邻有向关系和完整顺序。这样能定位改动究竟改善了哪个环节。代理分数的作用是**在相同训练包、相同模型和相同口径下比较方案**；它不需要冒充官方公式，仍然是有明确目标、可解释的研究指标。以下定义与 [`evaluate_baselines.py`](../evaluate_baselines.py)、[`evaluate_path_answer_pair.py`](../experiments/evaluate_path_answer_pair.py)、[`evaluate_sft.py`](../experiments/evaluate_sft.py) 逐项对应。

设第 $i$ 题预测答案为 $a_i$，金标答案集合为 $A_i$；预测链为 $c_i$，全部**原始完整**金标备选链为 $G_i$。多参考题对每项指标取某条真实金标的最佳匹配；预测链始终只有一条，训练目标也不把不同金标链拼接。设 $E(c)=[(c_1,c_2),\ldots,(c_{m-1},c_m)]$ 是一条链的**有向相邻步**。下表每个逐题值都在 $[0,1]$，除特别注明的原始余弦外。

| 方向和本地指标 | 实际计算公式 | 为什么适合本题 |
| --- | --- | --- |
| 答案字符 F1 $C_i$ | 先小写、只保留字母数字（汉字属于此类），按**字符多重集**计数。对答案 $a$、参考 $r$：$C(a,r)=2\sum_x\min(n_a(x),n_r(x))/(\sum_xn_a(x)+\sum_xn_r(x))$；两边都空取 1，单边空取 0；$C_i=\max_{r\in A_i}C(a_i,r)$。 | 对应官方“字符 F1”方向；保留重复字符计数，对长度和遗漏都有反应，适合比较具体答案文本变化。 |
| 答案语义 $S_i$ | 本地 BGE 编码向量先作 L2 归一化；$S_i=\max_{r\in A_i}\mathbf e(a_i)^\top\mathbf e(r)$。先求视图均值 $\bar S_v$，合成 80 分代理时再将该均值裁剪到 $[0,1]$。 | 对应官方“语义”方向，捕捉不同措辞表达同一含义的情况，补充字符 F1。 |
| 证据节点 F1 $N_i$ | $F_1(p,g)=2\lvert\operatorname{set}(p)\cap\operatorname{set}(g)\rvert/(\lvert p\rvert+\lvert g\rvert)$，两边空链取 1；$N_i=\max_{g\in G_i}F_1(c_i,g)$。 | 对应官方“证据节点”：是否找到了应引用的事件；有多个合法链时不强迫只认其中一条。 |
| 有向相邻边 F1 $D_i$ | $D_i=\max_{g\in G_i}F_1(E(c_i),E(g))$，$F_1$ 的分母和空集规则同上。 | 同时检查相邻性与方向，能发现“节点都对但顺序／连接错”的输出。 |
| 完整链匹配 $X_i$ | $X_i=\mathbf1[c_i\in G_i]$，即预测 ID 序列与某条完整金标**逐位相同**。 | 对应“结构与顺序”的严格端点，防止只靠局部边得分掩盖多跳链遗漏。 |

其中 `set_f1` 的代码分母是原链长度 $|p|+|g|$，分子用去重后的交集；合法证据链要求 ID 不重复，此时就是标准集合 F1。节点 F1、边 F1、答案 F1 分别对 gold 备选集取最大值，**可能由不同备选链取得各自最大值**；这是为了逐项诊断多参考题，不代表存在一条金标同时达到所有分项。完整链 $X_i$ 单独保证严格的联合顺序命中。

关键事实在不同研究阶段使用了两个清楚命名的版本。令题目给出的 `required_facts` 为 $F_i$。若 $F_i$ 为空，该题**不进入事实覆盖均值分母**，另报告有事实的题数；不能凭空填 0 或编造事实。

| 事实代理 | 逐题公式 $K_i$ | 使用场景和解释 |
| --- | --- | --- |
| **语义阈值覆盖** $K_i^{\rm sem}$ | $\frac1{\lvert F_i\rvert}\sum_{f\in F_i}\mathbf1[\mathbf e(a_i)^\top\mathbf e(f)\ge0.70]$ | 早期 DeepSeek 配对研究。希望允许同义改写，“0.70”是固定的探索阈值；同题两臂用同一阈值，因此差值可解释。 |
| **字面／字符覆盖** $K_i^{\rm lit}$ | $\frac1{\lvert F_i\rvert}\sum_{f\in F_i}\mathbf1[\operatorname{substr}(f,a_i)\lor C(a_i,f)\ge0.5]$，其中 $\operatorname{substr}(f,a_i)$ 表示事实原文是答案的子串。 | `evaluate_baselines.py`、SFT 评价和 80 分代理。计算透明、无需额外语义判别器，适合追踪答案是否明确写出给定事实；对改写敏感，数值常低于语义版本。 |

这两个版本分别回答“答案**语义上**是否接近事实”和“答案**明文**是否覆盖事实”，都是针对官方关键事实项的合理观测；它们的绝对值不能跨表混合。早期配对用 `SentenceTransformer` 的本地 BGE 归一化向量，SFT 评价用同一 BGE 系列权重的 CLS 向量、512-token 上限；即使都叫“语义余弦”，跨评价脚本的值也应先统一编码器再横比。SFT 报告记录超过 512 token 的语义文本数，以便判断这个代理的覆盖范围。

对于“拒答”，先分别统计**行为**与**正确性**。无 gold 集只能得到拒答数 $R=\sum_i\mathbf1[a_i=\text{“无法确定”}]$ 和拒答率 $R/n$。有 gold 时，历史通用评价脚本用 $y_i^{\rm chain}=\mathbf1[\forall g\in G_i,\ |g|=0]$ 表示“金标无非空证据链”，并计算 $\mathbf1[\mathbf1[a_i=\text{“无法确定”}]=y_i^{\rm chain}]$；早期配对脚本采用更严格的 $y_i^{\rm strict}=y_i^{\rm chain}\land\mathbf1[\text{gold 答案恰为“无法确定”}]$，避免把有文字解释但无链的题误记为正确拒答。两者衡量的是不同问题，不能把拒答**次数**当拒答**准确率**。本报告的流程配对结果沿用严格版；当前 SFT 评价脚本仍是无链版。后续跨方案主表采用**严格版**、无链版作为证据充分性诊断，并在正式 SFT 评价前统一代码口径；93 道解释性 `unanswerable` 另列一层。

### 2.2 如何汇总到公开权重，以及为什么这样设计

同一视图 $v\in\{A,B,C\}$ 下，先逐题算分，再对该视图题目取**宏平均**；事实覆盖仅对有 `required_facts` 的题求平均并同时报告分母。令这些均值为 $\bar K_v,\bar C_v,\bar S_v,\bar N_v,\bar D_v,\bar X_v$。可复算的五项代理为：

$$
P_v=25\bar K_v+10\bar C_v+5\operatorname{clip}(\bar S_v,0,1)+25\bar N_v+7.5\bar D_v+7.5\bar X_v,\qquad 0\le P_v\le80.
$$

$$
P_{ABC}=0.6P_A+0.3P_B+0.1P_C.
$$

前四个系数 **25／10／5／25**直接来自公开分项权重；官方在结构与顺序 **15** 分下提到因果边 F1、方向准确率和链路匹配，却没有给三者的内部权重及完整公式。我们把 15 **等分给有向边 F1 和整链匹配**，并未单独给方向准确率另算一项：前者奖励局部连接和方向，后者奖励完整次序与长度。两者互补，能解释“节点 F1 升了但长链被截短”这种失败，但也可能遗漏官方方向分项的独立影响。A/B/C 的 **0.6／0.3／0.1**直接采用公开档位权重，避免因测试题数 B 最多就让 B 自然主导总览。80 分之外的 confidence／拒答 20 分不硬凑：官方校准规则未知，拒答已作为单独诊断指标，故不能制造一个看似精确的百分制成绩。

这个 $P$ 是**按官方项目与权重组织的本地比较尺度**，实现见 [`score_proxy_from_diagnostics.py`](../experiments/score_proxy_from_diagnostics.py) 和 [`evaluate_sft.py`](../experiments/evaluate_sft.py)。它可用于同一固定划分上的消融排序、定位损失来源和作敏感性分析。事实缺项不是模型答错：若某视图所有题都缺 `required_facts`，当前脚本会把该项记为 0 并在报告标明无有效分母；出现这种情况应先看分项和覆盖率，不拿总数单独排方案。历史 100 题的 **34.842／34.498／40.513（满 80）**是把五项公式用于那批题的 `all` 组，**没有再按 A/B/C 加权**；将来包隔离 SFT 汇总才按 $P_{ABC}$ 合并。两种本地汇总都不用于“估”平台 59.55。

例如那批 100 题的 DeepSeek 字面事实覆盖均值为 **0.0623**，代入事实项得 $25\times0.0623=1.5575\approx1.558$。这个数字准确表达了**按本地明文规则，答案很少逐字覆盖 `required_facts`**，可用于比较提示是否补上事实；它不表示官方只会给 1.558 分。若没有加载语义编码器，`evaluate_sft.py` 会把 $P_v$ 留空，而不是把缺失的语义项擅自当零。

### 2.3 候选、盲测结构与配对差值如何计算

对有非空 gold 链的 $n$ 题，令 $G_i^+=\{g\in G_i:\lvert g\rvert>0\}$，设检索前 $k$ 个候选 ID 的集合为 $S_i^{(k)}$。**完整链候选覆盖**和**最佳链节点召回**分别是
$\frac1n\sum_i\mathbf1[\exists g\in G_i^+:\operatorname{set}(g)\subseteq S_i^{(k)}]$ 与
$\frac1n\sum_i\max_{g\in G_i^+}\lvert S_i^{(k)}\cap\operatorname{set}(g)\rvert/\lvert g\rvert$。所以“BM25 前 3 覆盖 42.37%”的含义是：在这 6339 道训练题中，约 42.37% 的题至少有一条完整金标路径的事件 ID **全部出现在候选中**；它不要求生成器真的选对、排对或回答正确。加入题目明示合法 ID 的实验检验“保留题目锚点”能否减轻固定 top-k 的漏召回。

小样本流程实验使用**同题配对**：对固定题集 $I$，$\Delta M=|I|^{-1}\sum_{i\in I}(M_i^{\rm 新}-M_i^{\rm 原})$。首组 **12 题＝四种主要题型各 3 题**；独立第二组 **11 题＝三种可回答题型各 3 题＋2 道合格拒答题**，因为新的合格拒答包不足以凑到 3 题。两组均按包隔离，排除前期探索包与拟合集完全相同的问题＋答案；先冻结题目再运行两个提示臂。这个设计让模型和题目难度在两臂抵消，并确保主要困难类型都能被观察，适合测试**流程改动的方向**；它不是按 760 题自然频率抽出的总体分数估计。分别列首组、第二组和合并值，正是为了检查初次正向信号是否能在新包上继续出现。

对无 gold 的 760 题，仍可严谨报告三个**行为量**：平均链长 $n^{-1}\sum_i|c_i|$；跨次“链完全相同”比例 $n^{-1}\sum_i\mathbf1[c_i^{\rm 旧}=c_i^{\rm 新}]$；A 档给定边支持率
$\sum_i\sum_{e\in E(c_i)}\mathbf1[e\in E_i^{\rm given}]/\sum_i|E(c_i)|$。最后一个是把全部输出相邻步汇总后求比例，**不是**逐题支持率再平均；它衡量生成链与题面边表的一致性，尤其适合核查提示是否真的改变了路径使用方式。因为 gold 中也有给定图缺步，它不充当正确率。时间成本记录实际生成秒数和 token 数；API 费用按各类已报告 token 数乘当时对应单价再除以一百万，缺失的重试用量使费用估计为下界。

### 2.4 数值 confidence 为什么只从验证集学

赛事原始 gold 有文字级别的 `confidence_level`，没有可直接监督的每题数值概率。训练时把“certain／probable／possible”拍成 0.9／0.6／0.3 会伪造标签。已实现的 [`calibrate_sft.py`](../experiments/calibrate_sft.py) 为将来的**固定 validation 预测**定义了一个可检查目标：非拒答题的局部联合成功
$y_i=\mathbf1[C_i\ge0.5\land X_i=1]$，即答案至少达到事先固定的字符匹配门槛，且完整证据链命中。按 A/B/C、再按预测链长度 $1,2,3+$ 分桶；长度桶至少 20 例才用它，否则回退到档位整体。桶内有 $s$ 个成功、$n$ 个有效样本时，以 Beta(2,2) 平滑得 $\hat p=(s+2)/(n+4)$，避免小桶输出武断的 0 或 1。拒答的 confidence 保持 JSON `null`。

校准器还按**材料包**分成五折，报告 $\mathrm{Brier}=N^{-1}\sum_i(\hat p_i-y_i)^2$；同包预测不会同时进入某折的拟合与检查。这里的 $\hat p$ 明确解释为“上述局部答案＋链联合成功代理的经验概率”，不是未经证实的官方 confidence 得分。**目前尚无正式 SFT 的 validation 预测，因此没有已拟合的校准结果。**

| --- | ---: | ---: | ---: |

这说明固定 `top_k=3` 很容易漏掉长链。学习式事件排序在 200 包留出审计里也曾将 A 档图条件下的候选完整链覆盖从 **41.42% 提至 74.41%**，但把候选提示交给 DeepSeek 的后续生成试验没有出现稳定的答案和链收益；C 视图的覆盖仅从 **25.35% 到 29.53%**。所以“检索能找到”只能作为流程改进的第一关。

较早的关系自然语言化、检索提示和“选链后锁链改答案”尝试留下了负结果。12 道不同包、同模型的干净配对题中，原输入→最终两阶段方案的答案字符 F1 **.2948→.2905**、边 F1 **.5685→.5476**、链完全匹配 **3/12→3/12**；锁链阶段没有带来稳定净收益。另一组 12 题的锚点与候选提示使链 exact **.5000→.4167**，节点 F1 **.8551→.7903**。这些数字样本很小，但足以阻止将“更多候选”“更多推理步骤”直接写成默认流程收益。

### 3.4 10 月 5—6 日：从合法训练原件重建 SFT 数据

模型外实验发现，题型、给定边和 gold 并非总是简单一致。于是先固定划分、保留原 gold，再生成与推理视图一致的监督数据。`experiments/finetune_split_20261005.json` 按**材料包及完全相同文档**分组，避免同一文档直接跨 fit、validation、holdout；各划分 **801／101／98 包**。训练、验证、留出只来自赛事训练集。测试集没有 gold，也不参加划分或超参数选择。

划分比例不是碰巧得到的。脚本先将每篇文档规范化后取 SHA-256，凡共享完全相同文档的材料包通过连通关系绑在同组；再按材料包领域前缀分层，以固定种子 `20261005` 打乱组，按**包数约 80%／10%／10%** 分配。组不可拆，因此实际得到 801／101／98，而非强行凑整到 800／100／100。这一分布让 fit 有足够样本学习，validation 可用于模型和校准选择，holdout 留作最后一次独立核查；领域分层避免某一领域集中落到单侧。跨包的“同问题＋同答案”并不等于共享完全相同文档，故 498 题保留并单列模板层结果，可以直接检查模型是否只记住问答模板。

`audit_training_data.py`、`prepare_finetune_data.py` 和 `sample_multireference_epoch.py` 可从原件重建这些数据。1000 包、7196 题的完整原始 gold 另存为忽略目录中的 sidecar，共 **13,336** 条备选链；训练目标不会把不同链拼接成一条“新链”。固定链与按种子／轮次选完整备选链均可重建。A/B/C 混合、给定图缺步、解释性无答案、多参考及同文问答都保留独立标记，以便以后做有意义的消融。没有引入外部问答、合成标签或 DeepSeek 输出，也没有凭类别造数值 confidence。

多参考抽样的规则也是确定的。对样本 $i$、训练轮次 $e$ 和可兼容完整链列表 $G_i^{(v)}$，取字符串 `seed:epoch:pack:sample_id:view` 的 SHA-256 前 8 字节为整数 $h$，选第 $h\bmod|G_i^{(v)}|$ 条链。换轮次可以覆盖不同的合法解释；固定种子和轮次又能逐字节复现。固定链对照与多参考版本保持同一问题、视图及训练预算，才有资格讨论“多参考是否帮助”。

选定 Qwen3.5-9B 后，用其 tokenizer 和 LLaMA-Factory 的实际聊天模板量测**完整输入加监督输出**，同时查证据所在文档／事件记录。初版位置审计只查文档，误把部分仅在事件记录中可见的 gold ID 记为未定位；修正后九个 split/view 的 gold ID 未定位数均为 **0**。长度结果说明为什么不能直接把所有行尾截到 8K：

| 划分／视图 | 完整消息 >8K | 完整消息 >16K | 若按 8K 尾截断，至少丢一处 gold 证据 |
| --- | ---: | ---: | ---: |
| fit A／B／C | 1800／1479／810 | 75／35／0 | 257／257／227 |
| validation A／B／C | 197／147／98 | 14／7／0 | 33／33／30 |
| holdout A／B／C | 239／203／73 | 4／0／0 | 25／25／21 |

混合训练不是把每道题的 A/B/C 三份同时塞进一轮。对题 $i$ 当前合法视图集合 $V_i$，赋公开权重 $w_A=0.6,w_B=0.3,w_C=0.1$，按 $\Pr(v\mid i)=w_v/\sum_{u\in V_i}w_u$ 选择**一种**视图；以种子、轮次、包和题号的 SHA-256 决定抽签，因此缺失视图的权重会重新归一化，运行结果也可复现。这个选择让每个问题在同一轮贡献一条监督，而 A/B/C 的总体出现频率又接近正式评分重要性；它既防止三视图重复令某题权重变成三倍，也不会把 C 完全忽略。两轮固定链混合源文件有 **11562** 行，实际 A/B/C 为 **6863／3524／1175**，即 **59.36%／30.48%／10.16%**，与目标 60%／30%／10% 接近。这是**训练分布的可检验设定**，不是官方规定的最优采样率；后续 A/B/C 分档指标可检验是否应调整。

这里的“两轮”是**构造样本时对同一 fit 题重复两次、每次重新抽视图／备选链**；正式 LLaMA-Factory 配置对这份混合文件只设置 `num_train_epochs: 1`。不能把“数据生成两轮”误写成“模型已经训练两轮”，更不能误写成已完成正式训练。

按实际 16K 模板，11562 行筛到 **11538** 行；**24** 行超过上限，明确写入 manifest 留待长上下文处理，没有静默截断。当前完整数据、sidecar、manifest 和 SHA 都位于 Git 忽略的 `outputs/`，GitHub 只有脚本、固定划分与记录。

到这里解决的是“监督数据是否可追溯、评估是否隔包、长材料是否被悄悄截掉”。下一步必须在实际选定的离线模型和 GPU 上核查能否训练；这些数据检查本身不说明模型会提分。

### 3.5 10 月 6 日：选 Qwen3.5-9B，接入有出处的微调实现

拟定一轮 fit 为 **11538 行、约 8282 万 token**，真实模板长度中位数约 **6538 token**、90 分位约 **11024 token**。单卡每次处理一行、梯度累积 8，计划优化器更新数 $\lceil11538/8\rceil=1443$。训练时长按长度分桶估算：若第 $b$ 桶有 $n_b$ 行、同长度压力步测得或插值得到 $t_b$ 秒，则纯样本计算约 $T_{\rm compute}=\sum_b n_bt_b$；中心估算约 **76 小时**，考虑桶内长度位置可在约 **60—93 小时**波动，再给优化器、存档、数据加载留余量，预算区间是 **70—100 小时／轮**。这解释了“只更新 LoRA 参数，为什么仍要数天”：冻结底座减少可训练权重与优化器状态，但 8282 万 token 的长序列前向和反向仍需计算。此区间不是全轮实测。`train_shutdown_guard.py` 已做“不真实关机”演练，要求训练进程成功退出、adapter 与训练状态齐全、最低步数达标，再检查 GPU 利用率≤5%、已用显存≤2048 MiB 且无计算进程持续 10 分钟。**正式整轮训练未启动，尚无包隔离 SFT 模型分数或数值 confidence 校准。**

### 3.8 当前流程和下一步微调如何衔接

离线推理按同一赛题材料构造输入：**A** 把题目条件化局部路径作为候选并保留原文／事件／给定边，**B/C** 沿用原输入；本地模型生成答案与证据链后，统一解析、必要时格式修复、检查证据 ID 并写入忽略目录。候选路径只是提示，不能把给定图中不存在的 gold 步骤自动判错。思考模式额外有 1024-token 两段预算；格式修复是在同一原始材料上重试，不引入外部答案。

正式微调拟采用已有上游 LLaMA-Factory 配置，流程与状态如下，命令和路径详见微调准备协议及配置文件：

例如 DeepSeek 优化版 $0.6\times63.85+0.3\times50.10+0.1\times52.24=58.564\approx58.56$；Qwen 有界思考相同计算得 $54.668\approx54.67$。**流程优化并没有在线上提高 DeepSeek 总分**：A 和 B 各下降约 1 分，C 小幅上升。按权重看，A／B／C 对本次总分变化分别约为 **−0.666／−0.375／+0.057** 分。只有 A 的输入增加了问题条件化路径；B/C 沿用原提示与运行器，却在另一次 API 运行中发生得分变化，因此 **−0.99 不能全部归因于 A 的流程改动**，跨次模型输出波动也是已观察到的混杂因素。A 本身下降 **1.11**，仍提示不能只以“边表支持率变高”决定是否采用新路径。

A 档同日原提示与新路径的**无 gold 输出对照**中，给定边支持比例 **0.8400→0.9787**，但平均链节点 **4.143→3.600**、平均答案字符 **246.04→218.32**，**51** 条链缩短、**14** 条延长；其中回溯题 126 道的平均链 **4.373→3.913**。这与“新提示可能过早截断完整上游链、减少事实解释”一致，是需要在有 gold 的验证包检验的**机制假设**；截图只给 A 总分，没有回溯、预测、反事实、无答案等细题型分数，不能声称哪一类实际失分。给定图本身存在缺边 gold，故更高的边表支持率也不是正确率。

Qwen **有界思考 54.67** 比非思考 **41.71** 高 **12.96**；A／B／C 都提高，但 C 只增加 **3.01**。A 提升 **15.94**，对加权总分增益贡献约 **9.56** 分，B 贡献约 **3.09** 分，C 约 **0.30** 分。既有输出诊断显示，A 反事实题 36 道的拒答从 **35→4**，B 反事实 55 道从 **52→21**，说明非思考模式在这些题上尤其保守；这是行为差异，平台未提供各细题型的正确率。C 中标记为 `unanswerable` 的 79 道题，拒答从 **73→38**，但 C 档分数仅小幅上升；这提示扩大回答范围可能有得有失，不能把“少拒答”直接当作越好。赛事训练集还有解释性无答案 gold，不能简单对该题型统一强制拒答。

当前**最佳已评分的本地离线模型输出**是未微调 Qwen3.5-9B 有界思考版。与 DeepSeek 优化研究版相比，它在 A／B／C 分别低 **1.99／6.66／7.04** 分；按权重折算，B 的差距约 **2.00** 分，是总差距约 **3.89** 分中最大的一块。A 已接近该研究对照，B 的因果关系识别和 C 的复杂／无答案判断值得优先在**固定训练验证集**检查。两份 Qwen 输出都用了优化后的 A 输入，未做同模型“原 A 提示 vs 新路径”的线上受控评分，不能由这四行反推 Qwen 应否撤销路径。非思考与有界思考同时改变了思考模板及采样，线上差值证实的是**端到端配置**差异，不是单一思考机制的因果效应。正式整轮 SFT 尚未运行；下一步应先用包隔离 validation 对照提示、生成和训练配置，再用 holdout 确认，不用这 760 题继续调参。

**下一道门槛是有 gold 的包隔离验证，而非再盲跑 760 道测试题。**既有划分已把训练集分成 fit／validation／holdout **801／101／98 包**，无需重新随机按题切分。validation 的 A/B/C 有效视图题分别 **709／709／706**，总计 **2124** 条；holdout 不参与配置选择。计划按如下顺序用较少预算先找出错误来源：

1. **冻结诊断小集。**从固定 validation 包中预先选约 **120—180 条有效视图题**，按 A/B/C、回溯／预测／反事实／无答案及可用的长材料、给定图缺步、解释性无答案、跨包模板问答标记分层；先定题号及分层，再看模型输出。按当前有界思考 **35.81 秒／题**机械外推，一次约 **1.2—1.8 小时**模型生成时间，实际因材料长度与加载会变动。完整 2124 条若同速约 **21 小时**，所以不宜一上来对每个方案全量推理。
2. **同题对照流程。**先在该小集给未微调 Qwen 建立带 gold 的 A/B/C 基线；A 用相同模型、生成设置与题目，配对比较原提示与新路径，专看完整上游链是否被截短；B 检查因果方向与缺失关系，C 检查冲突、反事实及无答案。分别报告答案字符 F1、语义、关键事实覆盖代理、证据节点／边 F1、完整链匹配、严格拒答正确率、推理 token／时间，并保存失败样本。自设代理用公开权重可形成最多 **80 分的比较尺度**，不充作官方得分；数值 confidence 只从 validation 研究校准。
3. **在全轮训练前定配置。**现有 SFT 数据和 LLaMA-Factory 配置使用 `qwen3_5_nothink` 模板，而线上最佳基模型输出使用有界思考。两者不能默认兼容；先用短训练／短验证核查 adapter 的格式、答案和证据质量，再确定一次主要训练的模板、视图混合和推理入口。多参考链、给定图缺步、同文问答、解释性无答案与长材料均保留标记，优先做验证集分层，不为每个消融各跑一轮 70—100 小时训练。
4. **只在证据支持后启动完整 QLoRA。**当前 16K fit 一轮估算 **70—100 小时**，另需验证推理和故障余量；初赛剩余不足一周，现实预算很可能只容纳一次主要完整训练。训练后与基模型在相同 validation 包同口径比较，方案确定后才用 **98 个 holdout 包**确认一次。保留负结果，不用 API 输出、760 道测试题或假造 confidence 标签训练，也不把平台反馈当逐题调参信号。未经用户授权，不再向赛事平台提交预测。
