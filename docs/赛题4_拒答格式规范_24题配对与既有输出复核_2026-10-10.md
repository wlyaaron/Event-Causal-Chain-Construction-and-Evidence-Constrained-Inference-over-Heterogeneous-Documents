# 赛题 4：拒答格式规范的配对实验与程序兜底

> 2026-10-10。只解决 **answer／evidence_chain／confidence 是否属于同一种输出格式**。是否应该拒答、限定解释是否正确，继续分别计分，不因格式规范而宣称改善。B 类候选链本轮不改。模型仍为 DeepSeek API `deepseek-flash`；gold 只用于本地抽样与事后评分，未进入请求。

## 结论

1. **不采用新增的格式提示词 V7。**在新的 24 道 fit 题上，基础 V4 与 V7 原始输出均为 24/24 有效；V7 多拒答了 1 道本可回答的题，答案语义略降。给 V4 继续加格式文字没有证明收益。
2. **保留保守的程序兜底。**程序只把“精确严格拒答但字段冲突”，或“空链、无具体事件 ID、以纯拒答句式开头”的响应规范成 `"无法确定" / [] / null`；不创造链，不编数值 confidence，不按 `question_type` 改答。它在先前 V6 的已保存 120 题里事后修复了 2 道原本无效、gold 确为严格拒答的输出；新 24 题没有触发修复，因此目前只能说**明确的格式冲突可以安全处理，尚无新题上的净提分证据**。
3. **收窄旧解析器的过宽拒答前缀。**旧 `task4_core.py` 遇到空链且 answer 以“无法确定”开头就清空后文，可能把含具体事件判断的反事实回答误作严格拒答。新版把这种情况留给原有校验与修复流程，不悄悄改写语义。旧版可由 Git 标签 `task4-candidate-answer-v2-frozen-20261010` 回退。

## 1. 先冻结新子集，再比较两种提示词

[冻结清单](../experiments/refusal_format24_20261010.json)在调用前按既定 fit 包挑选 **24 个不同材料包**：原始 gold 严格拒答 8 题、`unanswerable` 但有证据解释 8 题、其他可回答题 8 题，A/B/C 视图为 **14/7/3**。与旧 90、fresh30、ICL12 按包及规范化文档哈希隔离。按 gold 分层是为了同时检查“规范严格拒答”与“错误清空限定解释”的风险，故三类比例**不是自然分布**。清单只含题目、输入哈希和视图，没有 gold 答案或链。

两臂使用同一完整材料、同一问题、模型、JSON object 模式、默认思考设置及 8192 输出 token 上限；V7 只在 [V4 提示词](../experiments/prompts/task4_merged_rules_v4_draft_20261009.txt)末尾追加 **388 个字符**的[三条格式检查](../experiments/prompts/task4_refusal_format_v7_20261010.txt)。其余提示词逐字相同。预先写下的[判断标准与程序修正规则](../experiments/refusal_format24_protocol_20261010.md)不依赖本批输出。

## 2. 程序兜底到底修了什么

程序规则见 [`task4_refusal_format.py`](../task4_refusal_format.py)，已接入 [`task4_core.parse_prediction`](../task4_core.py)。它只在字段已经显示为纯拒答状态时整理格式：精确 `"无法确定"` 固定空链、null；空链且回答以预列拒答句式开头、没有具体事件 ID 时也规范成这一三元组。有链的限定解释保持原样；有具体事件判断却缺链、非法 JSON、截断都不被伪造为有效答案。原有解析器仍校验合法 ID、重复 ID、数值范围，并对无法修的输出触发既有修复流程。

对先前 V6 已保存的原始响应做**事后**重解析，结果如下。规则曾参考其中的错误，不能把这张表当成独立验证；它只确认代码处理了目标故障且没有在这 120 题中新增误拒。

| 已有 V6 题集 | 原始有效→规范后 | 严格 gold 命中 | 非严格 gold 误拒 |
|---|---:|---:|---:|
| 旧 90 题 | 80→81 | 19/24→20/24 | 1/66→1/66 |
| 另一 30 题 | 27→28 | 10/12→11/12 | 1/18→1/18 |

两道修复分别是 `public_safety_054_Q08` 和 `public_safety_118_Q08`：原答以“不能得出唯一确定结论……”开头，链为 `[]`，却给了数值 confidence；原始历史解析器判无效。程序统一为精确 `"无法确定"＋[]＋null`，两题的原始 gold 也恰为此格式。[逐题事后审计](../experiments/results/task4_refusal_format_existing_audit_20261010.json)

需要避免的反例是 `public_safety_169_Q03`。它的输出以“无法确定。”开头，随后讨论移除 D003 后 D006 是否发生，链却为空；gold 要求有依据的反事实回答。旧 `task4_core.py` 的宽泛前缀会直接压成严格拒答。新版看到具体事件 ID 不自动转换，保留为格式无效，交给原有修复流程。**格式程序不能替模型决定这个反事实是否成立。**

## 3. 现在采用什么、不采用什么

- **采用**：保持 V4 的现有拒答提示；使用收窄的程序规范作为罕见格式冲突的安全网。单元测试覆盖纯拒答、限定解释、具体事件判断、缺链答案与非法 JSON；在新 24 题上新版解析没有改动任何已有效输出，在旧 V6 的 120 题中只新增上述两道有效规范。
- **不采用**：V7 格式提示；按 `unanswerable` 题型或 answer 中的“无法”二字一律强制严格拒答；对缺链的具体解释编造证据 ID 或 confidence。
- **仍未解决**：模型何时选严格拒答、何时给限定解释。新 24 题里基础 V4 已有 6 道非严格 gold 误拒，V7 变 7 道。它们输出格式合法，却是内容／交付对象判断问题，不能用格式有效率掩盖。三类题被刻意等量抽样且此前训练题用于设计，所有数字都不能外推为官方测试分。
