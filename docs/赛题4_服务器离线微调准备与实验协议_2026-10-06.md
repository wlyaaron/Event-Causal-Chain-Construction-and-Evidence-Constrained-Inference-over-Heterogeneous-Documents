修正版完整审计报告 `tokenizer_audit.json` 的服务器 SHA-256 为 `325195d47b4d1e356aaacda946064661911a0afb2fcdf23726eefd368a46eb5c`。九组均没有超过 32K 的完整样本。C 视图的 gold 证据结束位置尤其靠后：fit 的第 95/99 百分位在消息的 95%/98% 处。审计没有截断材料。训练脚本只允许配置显式排除超长样本，并把逐题 ID 与 token 长度记录在 `input_manifest.json`；推理脚本对超限直接报错。未来显存允许时，应在完整长上下文训练或有独立验证的证据压缩策略之间作对照，不能用 gold 选推理文档。

多配置预检复用忽略目录 `outputs/sft_token_lengths.sqlite3` 中的长度缓存。缓存键同时包含 tokenizer JSON、chat 模板配置和完整消息摘要；首次计算仍执行真实 tokenizer 的模板前缀校验，随后不同 8K/16K 配置只复用同一消息的精确长度。缓存仅存 token 数，不存模型输出或 gold 衍生标签。

监督编码用一次完整 tokenization 的 offset 边界生成 assistant-only mask，跨 assistant 边界的 token 会报错。本地以相同 Qwen tokenizer 对全部 5,767 条 `fit_A`、各 500 条 `fit_B`/`fit_C` 样本与原双次编码逐 token 比对，输入 ID 和标签均一致，跨边界 0；服务器六项单元检查也通过。GPU 训练路径本身仍待显卡验证。

推理入口在不加载 GPU 模型的 `--check-only` 模式下，分别核对固定 validation 的 2,124 个和 holdout 的 2,089 个视图输入；以 32K 上下文预算并预留 1,024 个生成 token，两组超限均为 0。这是长度检查，不是预测或模型效果。

语义代理采用离线 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)（模型卡 MIT 许可），只作验证/留出评分，不作为训练数据。服务器权重 `model.safetensors` SHA-256 为 `354763b9b1357bc9c44f62c6be2276321081ed2567773608c0d0785b61d5a026`，tokenizer JSON 为 `48cea5d44424912a6fd1ea647bf4fe50b55ab8b1e5879c3275f80e339e8fae26`。相同短文本的归一化 CLS 余弦冒烟检查为 1.0，异文对为 0.6045；这是编码器运行检查，不代表本题答案语义效果或官方评分。编码器 512-token 上限下，评估报告会列出被截断的答案/参考文本数量。

当模型和校准器在 validation 上确定后，先用 `run_sft --split holdout` 写独立预测文件，再以 `evaluate_sft --split holdout` 做一次包隔离确认。`calibrate_sft apply` 只把已由 validation 拟合的数值用于有效预测；拒答的 confidence 为 `null`。任何正式赛事提交仍需用户授权。

**GPU 到位后才执行：** 先根据实际显存与 tokenizer 审计决定 `max_seq_tokens` 和 quantization，再以相同训练步数运行 A 单视图、A/B/C 固定链与逐轮多参考。另用 `build_sft_mix --a-graph-supported-only`、`--exclude-flag unanswerable_with_evidence`、`--exclude-flag step_absent_from_given_edges` 建立消融；长输入用相同样本共同覆盖层比较 8K/16K，同时报告被排除比例。配置已分别保存为 `task4_qwen3_4b_A_only.json`、`task4_qwen3_4b_fixed.json`、`task4_qwen3_4b_multiref.json`、`task4_qwen3_4b_graph_supported.json`、`task4_qwen3_4b_no_explanatory_unanswerable.json`、`task4_qwen3_4b_no_missing_graph_step.json`、`task4_qwen3_4b_fixed_16k.json`。训练前逐项执行 `train_sft --check-only`，其 `input_manifest.json` 记录超长剔除 ID、可用输入 token 与监督 token；训练本身若仍无 GPU 会明确失败。训练完成后 `training_cost.json` 记录实际消耗 token、耗时和峰值显存。每个模型对 `validation` 三视图全部预测，以 `experiments/evaluate_sft.py` 报答案字符 F1、BGE CLS 语义余弦、字面关键事实代理、节点/边 F1、完整链、拒答、输入/输出 token 与延迟。分别列 `same_question_answer_as_fit`、图缺步、解释性无答案和长输入层。公开权重的五项只能汇总为 **80 分代理**，置信度 20 分不能编造。挑选后再对 `holdout` 做一次确认并保留负结果。`experiments/calibrate_sft.py` 会核对预测恰好覆盖固定 validation 视图，只从这些预测与 gold 拟合数值置信度，并给出按包五折 Brier 代理；正式提交还需核对官方规则且必须经用户授权。

A 单视图基线读取原始固定链 `fit_A.jsonl`。其行数少于 800 步 × 8 个梯度累积微批次，训练会跨过一个数据轮次；多视图文件有两轮样本，但同一计算预算不会覆盖全部样本。因而比较时必须同时报告实际消耗 token 与所见样本比例，不能把文件名中的“两轮”误称为已完整训练两轮。

当前既有 DeepSeek API 的 59.55 是不同模型、盲测集上的平台研究基线，不能与本地代理分数作直接差值，也不能作为训练目标。

## 已知限制与待验证失败模式

- 当前 2 GiB 内存、0.5 核 CPU、零 GPU 的容器只支持数据和代码预检，尚无任何 SFT 权重、validation/holdout 模型预测或包隔离模型分数。4B 量化加载和 16K 训练的显存、内存峰值必须在 GPU 到位后实测；如果容器内存仍为 2 GiB，可能在加载阶段失败。
- 8K 训练会显式排除大量长样本，特别是 A 视图；若这一覆盖损失伤害长题，需要和 16K 同包同模型对照。原始 C 视图证据常在消息尾部，直接尾截断的风险已量化，不能作为默认处理。
- 789 道图缺步题与 93 道解释性无答案题是标注/输入关系不一致的风险层，不能等同为错误标签。隔离变体只检验其影响；原始固定链基线保留它们。
- 498 道跨划分同文问题加答案题保留，评估时分层呈现。若模板层收益显著高于其他层，应先检查泛化差异，不用这些标记修改固定分包。
- 既有新路径提示研究只在小样本改善节点/边代理，答案和完整链不稳定；它对离线 SFT 的影响仍须按相同验证集实测，负结果同样记录。
