# 赛题 4：A 候选链与 B/C 原版 V4 的三档冒烟

2026-10-10。将此前的 50 题研究方案接到测试集目录，先验证运行流程，不依据无 gold 的测试题判断答案正确性，也不提交赛事平台。

## 固定路由

| 测试集目录 | 输入和提示词 | 输出处理 |
|---|---|---|
| A | 完整材料；由给定有向图生成并排序前五条候选链；沿用 50 题实验的“单链、无额外 answer 段”用户前缀和 V4 system prompt | `task4_core.parse_prediction`，含保守拒答格式规范 |
| B/C | 完整材料；不生成候选链、不加 A 类用户前缀；V4 system prompt | 同上 |

三档用户输入均沿用 V4 实验的序列化方式，移去 `track` 字段；问题、原文、可见事件及关系保持完整。A 类候选只依据当前问题与可见图生成，gold 不进入输入。结果写入 Git 忽略的 `outputs/`，原始响应和 token 用量写入相邻的 `attempts.jsonl`；解析失败时保留进度并停止，不用无依据的严格拒答填充。

## 实际检查

- 全量无调用干跑：**760 题**，A/B/C 为 **210/350/200**；210 道 A 题均生成 5 条候选；最大用户输入 14,065 字符，未触发输入上限。

- 对生成的三题 JSON 再独立执行 `--validate`，**3/3 通过**；拒答格式单元测试 **7/7 通过**。这三个输出并未触发拒答规范，规范器本身由单元测试和此前保存输出的复核覆盖。

上述三题冒烟只证明三档路由、请求、解析、保存和校验贯通。结构有效不等于答案或证据链正确；这三题没有 gold，不能计算得分。

## 复现

在仓库根目录执行：

```powershell
python -m experiments.run_task4_v4_candidate_test --dry-run
python -m experiments.run_task4_v4_candidate_test --validate --output outputs/task4_v4_candidate_test_smoke.json
python -m experiments.run_task4_v4_candidate_test --all --dry-run
```

默认真实运行只选每档首题各一道，输出 `outputs/task4_v4_candidate_test_smoke.json`。完整运行需另给输出路径并使用 `--all`；中断后同参数可从 `.partial` 续跑。提示词、输入和候选代码哈希记录在续跑元数据中，避免更换方案后混用结果。
