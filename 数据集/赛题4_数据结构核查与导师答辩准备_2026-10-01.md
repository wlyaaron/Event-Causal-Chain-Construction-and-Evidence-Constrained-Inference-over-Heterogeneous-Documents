# 赛题4数据结构核查与导师答辩准备（2026-10-01）

## 一分钟汇报稿

赛题名称是“面向多源异构文档的事件因果链构建与证据约束推演”。输入不是单篇阅读理解，而是按主题打包的多篇文档和问题；系统要给出简洁答案、从原因到结果排列的事件证据链，以及置信度。A档给原文、事件和因果边，主要考证据链选择；B档按官网设计给事件但隐藏因果边，考因果方向与多跳组链；C档只给原文和问题，增加反事实、冲突信息、无答案和干扰项。评分不仅看答案文本，还看证据链和拒答是否有依据。官网设定 A/B/C 的**评分权重**为 60%/30%/10%，实际测试集**主题包数量**为 30/50/20，不能混为一谈。[官方赛题说明](https://www.heywhale.com/org/cunsl/competition/area/6aba35f66e5beff2fca5b1e8/content/2)

本地下载内容位于 `D:\邓锦亮\数据集`。实查训练集为 **1000 个主题包、9340 篇 TXT、9572 条事件、12456 条关系、7196 个问题及同数标准答案**；抽样测试集为 **100 个主题包、1045 篇 TXT、760 个问题**，无标准答案。官网的“训练约7180问答”与实查接近；官网写训练集“10000多篇文档”，本地实查是9340篇，建议以实物统计汇报并说明版本可能不同。测试集 11 个领域齐全；训练集 4 个主要领域共944包，另外 7 个领域各8包，共56包。

## 本地文件究竟长什么样

```text
数据集/
├─ 训练集/
│  └─ 公共安全_001/                 # 一个主题包；全训练集共1000包
│     ├─ D001.txt … D009.txt       # 多篇原文，篇数因主题而异
│     ├─ 事件列表.json             # 事件及原文位置
│     ├─ 事件因果关系列表.json     # 有向因果边
│     ├─ 问题.json                 # 待回答问题
│     └─ gold/问答对_答案.json    # 标准答案、可接受证据链、事实标注
└─ 抽样测试集_100/
   ├─ 测试集A_基础/                # 30包 / 210题；原文+事件+因果边+问题
   ├─ 测试集B_推理/                # 50包 / 350题；实际仅原文+问题
   └─ 测试集C_鲁棒/                # 20包 / 200题；实际仅原文+问题
```

训练集各包都有上述 3 个 JSON、若干 TXT 及 `gold` 答案。原文数量为每包 **5—15篇**，多数为 8—10 篇；事件为每包 **5—26条**。不能假设每篇文档恰好对应一条事件：1000包中有92包的事件数与文档数不同。测试集 A 的每包有 5 或 10 篇、7 题；B 每包 8—10 篇、7 题；C 每包 13—14 篇、10 题。训练和测试 JSON 均可解析，测试 760 个 `sample_id` 在测试集内部互不重复。

### 五类文件的字段与关联

| 文件 | 一条记录的关键字段 | 用途 |
|---|---|---|
| `D001.txt` 等 | 新闻/行业材料全文 | 最终证据文本；`D001` 是包内文档编号，不是全局编号 |
| `事件列表.json` | `event_id`, `doc_id`, `event_type`, `trigger_word`, `argument`, `occur_time`, `start/end`, `source_spans` | 从文本抽取的事件节点；`argument` 常有主体、地点、内容、影响；`source_spans` 指向原文片段 |
| `事件因果关系列表.json` | 常见为 `cause_event_id`, `result_event_id`, `causal_type`, `confidence_level` | 有向边，例如 `D001 → D002`；`certain/probable` 是部分边的等级 |
| `问题.json` | `sample_id`, `pack_id`, `question_type`, `reasoning_type`, `question` | 要答的问题；类型包括回溯、前瞻、反事实、无答案等 |
| `gold/问答对_答案.json` | `answers`, `answer_facts`, `evidence_chains`, `annotations`, `confidence_level`，并重复题目信息 | 训练监督和离线分析；`evidence_chains` 可以有多条可接受路径 |

以 `训练集/公共安全_001` 为例，D001 是客船倾覆事故，D002 是追责问责，边表含 `D001 → D002`，问题会追问二者是否因果、反事实移除 D001 会如何、以及哪些事件形成多跳链。`gold` 对一题可给多条合法链，例如到 D009 的链可以是 `[D001,D003,D004,D009]`，也可以是 `[D001,D002,D009]`。仅靠事件发生先后不够，必须能在文本或边表中找到支持方向的证据。无答案题应明确拒答。

### 提交文件与评分

官网要求提交**单个 UTF-8 JSON 数组**，每题一条：`sample_id`、`answer`、`evidence_chain`（有序事件 ID 数组）、`confidence`（0—1 或 null）、`question_type`。无答案时 `answer="无法确定"`、`evidence_chain=[]`、`confidence=null`。官网评测说明中每档的答案正确性、证据链、置信度及拒答分别占 **40/40/20**；证据链可与多条标准链中最有利的一条比较。页面也明确竞赛预测不得直接使用闭源 API 模型，开源模型和公开外部数据须注明来源，作品需可复现。[官方提交与评测说明](https://www.heywhale.com/org/cunsl/competition/area/6aba35f66e5beff2fca5b1e8/content/2)

## 必须主动说明的差异和数据质量问题

1. **B档实物缺事件列表。**官网任务B写“提供原始文档和事件列表，但不提供完整因果边”；本地50个 B 档主题包全都只有 `问题.json` 与 TXT。实际输入因而更接近从原文抽取事件，再推理边。应以当前文件为准准备读取程序，同时向组委会核实是否缺文件、是否后续补发。
2. **`sample_id` 跨训练/测试不保证唯一。**本地 7196 个训练题内部无重复，760 个测试题内部无重复，但两部分共有 **263 个相同 ID**，且仅1对问题文本完全相同。例如 `diplomacy_001_Q01` 在训练和测试中问的是不同问题。提交按测试集的 `sample_id`，内部存储须用“划分 + 主题包 + sample_id”作复合键；绝不能用训练答案按同名 ID 直接填测试题。
3. **训练标注存在字段变体与不一致。**关系表中有 **240 条**使用 `effect_event_id`/`relation_type` 等另一套字段，而非标准 `result_event_id`/`causal_type`；标准关系对象也有置信度缺失，`gold` 的置信度除官网列出的 `certain/probable/possible/null` 外，还出现 `high`、`medium`。解析时要做字段归一化和缺失处理。
4. **不能把金标当成无误的现实因果真值。**归一化两种关系字段后，训练金标的证据链中仍有 **805 条链**含至少一段未出现在该包因果边表中，**18 条链**引用了该包事件表不存在的事件。例：`训练集/公共安全_001` 的边表有 D003（2002-12-30 调查）→ D004（2002-12-11 救治），时间顺序与通常的因果解释冲突；对应金标又把它列为多跳路径。另有前瞻题把截断日之后发生的 D002/D003/D004 写进“已知”列表。汇报时称为**待复核的标注/时间一致性问题**，不宜以单例推断整个数据集都错误。
5. **来源与标注流程的可验证性有边界。**官网称材料来自公开报道等，采用双盲标注及专家审核；本地文件只有文档正文和结构化 JSON，没有逐篇原始 URL、刊发存档或标注流程记录。可以引用官网声明，但不能独立证明每篇材料都是真实新闻或标注均经双盲审核。部分文本有相似的固定段落，真实来源需另行核验。

核查范围：遍历本地全部训练/测试包和 JSON；对测试 1045 篇 TXT 与训练 TXT 做逐字哈希比较，未发现完全相同的文件。**这只排除逐字相同，不排除同主题改写或语义重合。**以上数据质量数字是机器结构核查，尚未逐条人工裁定语义合理性。

## 导师可能追问：简明回答

**Q1：这究竟是抽取任务、图推理，还是问答？** 以问答提交为统一出口，内部包含事件识别、事件对齐、因果方向判断、路径搜索、答案生成和拒答。A档可直接利用已给图，B/C需要承担更多结构恢复工作。

**Q2：什么叫“多源异构”？** 当前可见实物主要是多个 TXT 文档加结构化 JSON 标注，主题跨11领域。网页使用“多源异构”描述来源和内容；本地并未看到 PDF、图像或音频等多模态文件，不能把它讲成多模态比赛。

**Q3：事件 ID、文档 ID、问题 ID 如何对应？** `doc_id` 指向包内 TXT；`event_id` 指向包内事件，因果边和证据链引用 `event_id`；`sample_id` 是题目提交键。`D001` 可在不同包重复，训练/测试的 `sample_id` 也有重复，因此处理时加上划分和主题包。

**Q4：为什么先后发生不等于因果？** 时间是必要的排错线索，但还要有原文依据或给定因果边。`D001` 先于 `D002` 不能单独证明 `D001 → D002`；反例和干扰事件也会同时出现。对时间逆转的标注要复核。

**Q5：前瞻题怎么避免“看见未来”？** 先解析题目规定的观测截断点/可见事件，构造只含该时点以前证据的输入，再推断后续。当前文件有个别题的“已知”列表与日期冲突，需分开记录并向组委会核实评分口径。

**Q6：无答案和反事实应如何表达？** 无证据时说“无法确定”，空证据链、null置信度；反事实只能说现有链条支持“风险/可能性改变”，避免把移除一个节点写成现实世界中必然不存在所有下游事件。

**Q7：数据规模与评分权重为何不同？** 100测试包分 A30/B50/C20，对应问题数 210/350/200；60/30/10 是官网给出的分档加权公式。每档可能先算分，再加权，不能根据样本数推断最终权重。

**Q8：当前最需要确认什么？** 首先确认 B 档事件列表是否漏发，以及 B/C 在没有事件表时证据链事件 ID 的生成与判定口径；其次确认 JSON 字段变体、时间反向边和跨划分重名 `sample_id` 是否有官方修订或评分容错。提交格式与评分脚本发布后再做最终实现对齐。

## 汇报时可现场打开的四个文件

1. `训练集/公共安全_001/D001.txt`：原文长什么样。
2. `训练集/公共安全_001/事件列表.json` 与 `事件因果关系列表.json`：事件节点与有向边如何落地。
3. `训练集/公共安全_001/问题.json` 与 `gold/问答对_答案.json`：问题、答案事实、多条证据链如何配对。

## 2026-10-02 补充：多条证据链与 `start/end`

**一个问题为什么有多条 `evidence_chains`？** 这是同一题的多条备选证据路径，不是要求一次提交所有路径。以 `训练集/公共安全_001/gold/问答对_答案.json` 的 Q01 为例，目标是解释 D009，金标列出 `D001→D002→D009`、`D001→D003→D004→D009`、`D001→D003→D009`、`D001→D004→D009` 和 `D001→D009`。这些路径在该包的关系表中都有相应的有向边。官方评分会在多条可接受标准链中选择与提交链最匹配的一条；提交格式里的 `evidence_chain` 是**一条**有序路径。`D001→D009` 虽被列入金标，但相对于题目“完整证据链”的措辞很短，且长链中有时间逆转标注，因此研究和汇报时应区分“评测接受”与“真实因果解释充分”。

**事件列表的外层 `start/end` 是什么？** 设计意图是该事件 `trigger_word` 在 `doc_id` 对应原文中的字符区间，采用从0开始、`end`不包含在内的切片约定。例如 `公共安全_001/D001.txt` 中 `start=5,end=7` 切出“倾覆”。`source_spans` 里每个字段也有自己的 `start/end`，可定位“主体”“地点”等原文片段；它与外层坐标不是同一字段。

**使用偏移时要特别小心换行和标注误差。** 同包 D002 的外层 `start=173,end=175`：保留原文件 CRLF 换行时可切出“追责”；其 `source_spans` 的触发词位置却是 `170:172`，只在把 CRLF 规范成单个 LF 后能切出“追责”。全训练集核查显示：外层偏移有5910条在保留原始换行时匹配、39条仅在规范换行后匹配、2519条在两种方式下都不匹配、707条为空；另外397条事件指向本包不存在的 TXT。故 `start/end` 应理解为**原文定位标注的意图**，不能无条件当作准确索引；真正引用原文时需核对 `doc_id`、`trigger_word`、`source_spans` 与文本片段。
